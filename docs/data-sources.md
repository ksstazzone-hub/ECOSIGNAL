# Data Sources and Coverage Limits

The platform queries provider APIs; it does not infer a provider's geographic completeness from the API's advertised reach. Connector limits below are ECOSIGNAL client limits, not claims about provider quotas. Provider terms, API behavior, collections, and license metadata can change; re-check the live provider documentation and each dataset's metadata before an operational deployment.

| Source | Implemented capability | Access, licensing, and limitations |
| --- | --- | --- |
| GBIF | `GET https://api.gbif.org/v1/occurrence/search`; bounding coordinates, event-date range, scientific-name filter, coordinate requirement. Client requests at most 200 records per source/bounding box; connector protocol allows at most 300. | Public search API; occurrence search does not need an API key. Large downloads have separate workflows and conditions. Dataset/record licenses may be CC0, CC BY, CC BY-NC, or otherwise constrained; retain each returned license and dataset key. Temporal coverage and coordinate precision depend on each contributing dataset. Occurrence counts do not measure abundance or survey effort. |
| OBIS | `GET https://api.obis.org/v3/occurrence`; WKT bounding polygon, date range, scientific-name filter. Client caps each response at 500. | Public marine occurrence API. Marine emphasis is not complete ocean coverage. Record and dataset licenses/provenance can vary. Spatial uncertainty and event-date precision are source-specific; use `coordinateUncertaintyInMeters` where present. |
| iNaturalist | `GET https://api.inaturalist.org/v1/observations`; bounding coordinates, `d1`/`d2`, scientific-name filter. Client requests the first page with at most 200 observations. | Community observations are affected by observer effort, access, taxonomic activity, and quality grade. License is observation-specific (`license_code`); attribution and terms apply. API quotas/policies can change; deployments with many users must add shared throttling and caching. Dates and coordinate precision vary by observation. |
| NASA Earthdata / CMR | `GET https://cmr.earthdata.nasa.gov/search/granules.json`; spatial bounding box and temporal granule discovery, capped at 100 metadata entries per request. | CMR search metadata is publicly searchable; individual assets may require Earthdata Login. CMR does not provide one common resolution, temporal range, license, or access policy: inspect the selected collection and granule metadata. Catalog discovery is not measurement ingestion. |
| Copernicus Data Space STAC | `POST https://catalogue.dataspace.copernicus.eu/stac/search`; bbox and date-range item discovery, capped at 100 entries per request. | STAC items describe collections/products; download/service authentication and terms vary. Spatial resolution, revisit, time coverage, processing level, and usable bands are collection-specific. Sentinel-2, for example, has bands at 10/20/60 m; that does not make every band or acquisition available for every region/date. |
| NASA GIBS | The map offers dated MODIS Terra and VIIRS Suomi-NPP true-color WMTS tiles as optional visual context. | Tiles are not normalized observations, ecological metrics, or anomaly findings. Product availability is time-dependent and may be affected by cloud/sensor conditions. NASA GIBS/Earthdata attribution is shown on the map. |
| User datasets | `POST /api/datasets/import` accepts point GeoJSON FeatureCollections with explicit property mapping; `dataset_type` supports occurrences or environmental measurements. | Requires an import token, declared license, source metadata, and declared source EPSG. Original feature payload and schema mapping are retained. The importer does not certify the license, units, taxonomic identity, or scientific validity. |
| Future climate, national, and regional sources | Connector catalog metadata and normalized contracts allow additional REST/STAC adapters without changing core observation tables. | No single global climate/environment API is presumed. Add sources only with product-specific access, license, spatial/temporal resolution, quality flags, and provenance documented. |

## Coverage Interpretation

For biodiversity searches, the app requests only the first bounded page from each selected provider and exact-clips returned coordinates to the selected geometry. `source_reported_count` is the providers' count for queried boxes and may overcount a non-rectangular study area; the user interface reports only retrieved points inside the geometry. A result of zero is `no_usable_data` only when all selected providers responded. Provider failures produce partial/unknown status, never a zero-data conclusion.

For NASA/Copernicus, the app returns metadata search results only. It does not claim that a catalog item is downloadable, has sufficient spatial resolution, covers the entire study polygon, or contains an ecological signal. Environmental measurements must be uploaded with documented variable, unit, time, uncertainty, source, and license before an analysis module can use them.

## Administrative Boundaries

No boundaries ship in the database. A data administrator can import a verified GeoJSON FeatureCollection from sources such as geoBoundaries (check current release, ADM level, attribution/license, and field schema) or an appropriate UN/national authority. Supply the actual source version and license via the protected reference-layer endpoint. Imported boundaries are not overwritten across versions. Search only returns boundaries that have actually been imported; blank results mean unavailable reference data, not a missing country.
